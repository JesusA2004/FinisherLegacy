# Finisher Legacy API v1

Base URL: `/api/v1`

Este es el contrato que consumirán la app iOS/Android, otros sitios de Finisher Legacy y futuras integraciones. Cada endpoint reutiliza los mismos Services/Actions/Policies/Form Requests que la web Inertia — nunca hay lógica de negocio duplicada entre la web y la API.

## Autenticación

Autenticación por token via [Laravel Sanctum](https://laravel.com/docs/sanctum) (tokens personales, no cookies de sesión). Cada request autenticado debe incluir:

```
Authorization: Bearer {token}
```

Los tokens no expiran automáticamente (configurable en `config/sanctum.php`). El cliente es responsable de invalidarlos vía `POST /auth/logout` cuando el usuario cierra sesión.

## Formato de respuesta

**Éxito (recurso único / acción):**

```json
{
  "data": {},
  "message": "Mensaje opcional en español, o null",
  "meta": {}
}
```

**Éxito (listas paginadas):** formato estándar de Laravel API Resources — nunca envuelto dos veces.

```json
{
  "data": [],
  "links": { "first": "...", "last": "...", "prev": null, "next": null },
  "meta": { "current_page": 1, "last_page": 3, "per_page": 20, "total": 45 }
}
```

**Errores de validación (422):**

```json
{
  "message": "Los datos proporcionados no son válidos.",
  "errors": { "email": ["El campo email es obligatorio."] }
}
```

**Otros errores:** `{"message": "..."}` con el status HTTP correspondiente. Nunca se exponen excepciones internas ni stack traces.

| Status | Significado |
|---|---|
| 200 | Éxito |
| 201 | Recurso creado |
| 204 | Éxito sin contenido |
| 401 | No autenticado (token ausente/inválido) |
| 403 | Autenticado pero sin permiso, o recurso bloqueado |
| 404 | No encontrado |
| 409 | Conflicto (p. ej. Legacy Code ya reclamado por otro usuario) |
| 422 | Validación fallida |
| 429 | Límite de solicitudes excedido |

## Identificadores públicos

Las URLs nunca dependen de IDs incrementales predecibles:

- **Medallas**: `uuid` (no el `id` autoincremental).
- **Legacy Code**: `code` (p. ej. `Q8K2MX7P`), atemporal — sobrevive cambios de username/email/dispositivo.
- **Eventos**: `slug`.
- **Perfiles**: `username`.

## Fechas

ISO 8601 para timestamps (`created_at`, etc). Fechas sin hora (`event_date`) en formato `YYYY-MM-DD`.

## Rate limiting

| Limiter | Aplica a | Límite |
|---|---|---|
| `api` (default) | Endpoints autenticados generales | 60/min por usuario o IP |
| `api-register` | `POST /auth/register` | 5/min por IP |
| `login` (compartido con la web) | `POST /auth/login` | 5/min por email+IP |
| `api-legacy-lookup` | `GET /legacy-codes/{code}` | 30/min por IP — evita enumeración masiva de códigos |
| `api-claim` | `POST /legacy-codes/{code}/claim` | 10/min por usuario |

## Auth

### `POST /auth/register`

Crea un usuario, le asigna el rol `athlete`, emite su Legacy ID y un token de API. Usa exactamente la misma acción (`App\Actions\Fortify\CreateNewUser`) que el registro web.

**Body:** `first_name`, `last_name`, `email`, `password`, `password_confirmation`.

**201** → `{ data: { user: {...}, token: "..." }, message: "Tu Legacy comienza aquí." }`

### `POST /auth/login`

**Body:** `email`, `password`.

**200** → `{ data: { user: {...}, token: "..." } }`
**422** si las credenciales no coinciden (mismo mensaje que la web, `lang/es/auth.php`).

### `POST /auth/logout` 🔒

Revoca el token actual (no todos los tokens del usuario).

### `GET /me` 🔒

Devuelve el usuario autenticado.

## Perfil (propio)

### `GET /profile` 🔒

`data` es `null` si el usuario aún no tiene Legacy Profile.

### `PATCH /profile` 🔒

Mismas reglas de validación que `dashboard/profile` en la web (`UpdateAthleteProfileRequest`). Acepta `multipart/form-data` para `profile_photo`/`cover_photo`.

## Perfil público

### `GET /athletes/{username}`

Público, sin autenticación. Devuelve `404` si el perfil no existe o es privado (no revela cuál de las dos razones).

```json
{
  "data": {
    "profile": { "name": "...", "username": "...", "bio": "...", "city": "...", "sport": "...", "photo_url": "...", "cover_url": "..." },
    "stats": { "medals": 3, "events": 1 },
    "medals": [{ "id": "uuid", "title": "...", "distance_label": "21K", "event_date": "2026-01-01", "thumbnail_url": "..." }]
  }
}
```

## Medallas 🔒

Todos los endpoints de medallas requieren autenticación y solo operan sobre las medallas del usuario autenticado (`MedalPolicy`).

- `GET /medals` — paginado, 20 por página.
- `POST /medals` — mismas reglas que el wizard web (`StoreMedalRequest`); `front_image` obligatoria.
- `GET /medals/{uuid}`
- `PATCH /medals/{uuid}`
- `DELETE /medals/{uuid}` — archiva (soft delete), nunca borra el registro.

---

## Eventos

### `GET /events`

Público. Query params: `q` (busca por nombre/ciudad), `sport` (slug), `status` (`upcoming`/`ongoing`/`finished`). Sin `status`, oculta eventos ya finalizados por defecto.

### `GET /events/{slug}`

Público. `404` si el evento no está publicado.

---

## Legacy Codes

### `GET /legacy-codes/{code}`

Público. Resuelve el estado de una placa desde su Legacy Code — este es el endpoint que respalda `https://finisherlegacy.com/l/{code}` y, eventualmente, los Universal/App Links de la app móvil.

### `POST /legacy-codes/{code}/claim` 🔒

Vincula la placa/Legacy Code al usuario autenticado. Transaccional con lock de fila; si la placa tiene datos de evento/tiempo/ritmo (integrada o quick), crea automáticamente la Medalla correspondiente — nunca se le vuelve a pedir esa información al usuario.

- Idempotente si ya la reclamó el mismo usuario (200, sin duplicar la medalla).
- **409** si ya la reclamó otro usuario (sin revelar quién).
- **403** si el código está bloqueado/cancelado/reemplazado.
- **404** si el código no existe.

```json
{
  "data": { "legacy_code": "Q8K2MX7P", "medal": { "id": "uuid", "...": "..." } },
  "message": "Esta historia ya forma parte de tu Legacy."
}
```
